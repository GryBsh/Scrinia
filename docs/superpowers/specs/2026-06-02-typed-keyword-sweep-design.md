# Design: Anchors-vs-Typed-Keywords Single-Pass Sweep (LoCoMo dialog)

- **Date:** 2026-06-02
- **Status:** Approved (design); pending implementation plan
- **Scope:** `benchmarks/Scrinia.Retrieval.Benchmarks/` only — no Scrinia.Core / prod changes

## Context

Across this session we converged on a write-time architecture question: scrinia is always
called from an agent, so the agent should supply retrieval metadata at write time. Two
candidate signals exist:

- **Anchors** — free-form query-vocabulary phrases ("how do lifecycle hooks work").
  Already implemented in the bench agent harness.
- **Typed keywords** — structured `prefix:value` tags (`entity:mary`, `topic:home renovation`)
  describing content *aboutness*, agent-normalized.

The cross-encoder is **settled** (works well; stays on). The open question is **anchors vs
typed keywords as the write-time contribution**, cross-encoder held constant. The user's
token-economy argument: anchors are sentences (many output tokens, most of which are
stopword scaffolding that evaporates at index time); typed keywords are a handful of tokens
carrying nearly all-distinct retrieval signal — so at retrieval parity, typed keywords win on
generation speed/cost at every write.

A prior session established LoCoMo-dialog cross-encoder numbers (CE-alone 60.7/65.9/72.9/0.563;
CE+anchors 63.8/69.7/78.5/0.587). MemBench is a poor surface to discriminate the two signals
because, with the cross-encoder on, its candidate pool is already near-full (R@50 ~97-98%) —
there is little headroom for *either* write signal. LoCoMo dialog is the discriminating surface
because its pool has real gaps (finding #4).

## Goal

Run a four-cell sweep on LoCoMo dialog with the cross-encoder on, sharing one agent generation
pass, to measure whether typed keywords match or beat anchors as the write-time signal — under
**production-faithful indexing weights**, so the result predicts a real switch decision.

## Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Type vocabulary | `entity:` + `topic:` | `entity:` covers people/places/objects, `topic:` covers activities/themes. Leanest, lowest agent variance, maps directly to "aboutness". No `date:` (weak tokenization), no `related:`/graph (gated separately). |
| Generation mechanics | **B — two focused calls, each cached** | Each signal generated by its *own best prompt* → fair A/B. Cache persists across the 4 config runs, so each signal is generated exactly once for the whole sweep (the "single pass" guarantee). Enables clean per-signal output-token measurement (the token-economy metric). |
| Index weights | **Prod-faithful, asymmetric**: typed-keyword value tokens +5, anchors +2 | Mirrors prod (`Store`: agent keywords +5, anchors +2). We compare the signals *as deployed*, not weight-equalized — a stronger indicator of real-world gains. Explicitly endorsed by the user. |

## Design

### 1. New agent op — `GenerateTypedKeywordsAsync`

- `IAgentHarness`: add `Task<IReadOnlyList<string>?> GenerateTypedKeywordsAsync(string content, CancellationToken ct)`,
  returning `["entity:mary", "topic:home renovation", ...]`. `NoOpAgentHarness` returns null.
- `AgentModes`: add a `TypedKeywords` flag alongside `Anchors`/`Rewrite`/`Hyde`. Update
  `AnyEnabled` and `Label()` (new labels: `typed`, and combos like `anchors+typed`).
- `AgentPrompts`: add `TypedKeywordsSystem`, `TypedKeywordsUser(content)`, `ParseTypedKeywords(raw)`.
  - System prompt: list the entities and topics this memory is *about* — `entity:<name>` for
    people/places/objects, `topic:<theme>` for activities/themes; one per line, lowercase,
    plain text, no commentary. Built from **document content only** (anti-data-leakage contract,
    identical to anchors — never sees the gold answer set or question dataset).
  - Line-mode output (small models parse it more reliably than JSON; matches the anchors op).
  - `ParseTypedKeywords`: split lines, strip list markers, validate prefix ∈ {`entity`,`topic`},
    lowercase, trim, dedup (case-insensitive), drop malformed/empty, cap at `MaxTypedKeywordsPerDoc`
    (~8). Returns empty array → null at the cache layer (mirrors `ParseAnchors`).
- `LlmAgentHarness.GenerateTypedKeywordsAsync`: mirrors `GenerateAnchorsAsync` — cache op key
  `"typed"`, content-hash key, dedicated timeout + ~200 max-token budget, `jsonMode: false`,
  null result cached to skip retries.

### 2. Ingest wiring

- `IRetriever.IngestAsync`: add an overload accepting `IReadOnlyList<string>? agentKeywords`
  alongside the existing `agentAnchors`. Existing overloads delegate with `null`.
- `ScriniaRetriever.IngestEntryAsync` (accepts `agentKeywords`):
  - Append typed keywords to `entry.Keywords` (auto-extracted keywords ∪ typed keywords), so the
    field scorer's exact (+40) / contains (+12) paths see them.
  - Seed each typed keyword's **value tokens** into the merged TF dict via
    `TextAnalysis.IndexTokensForKeyword(kw)` at **+5**. This is where the `IndexTokensForKeyword`
    helper (already shipped to Core) reaches the bench — the bench retriever builds `ArtifactEntry`
    directly and does *not* route through `MemoryTools.Store`, so the helper must be invoked here
    explicitly. Anchors continue to seed at +2 (unchanged).

### 3. Config toggle (CLI)

- `RetrieverFactory.ParseAgentMode`: accept `typed` and comma-separated combos
  (`anchors`, `typed`, `anchors,typed`), in addition to the existing `off`/`rewrite`/`hyde`/`all`.
- `ModeLabel` already emits `agent-{label}`, so result files self-distinguish
  (`…__chunked_ce_agent-typed`, `…__chunked_ce_agent-anchors+typed`).
- `BenchmarkRunner.IngestHaystackAsync`: call both `GenerateAnchorsAsync` and
  `GenerateTypedKeywordsAsync` (each gated internally by its mode flag), pass both into the new
  ingest overload — same structural shape as today's anchor-only call.

### 4. Run plan (4 cells, one shared agent cache)

Constant across cells: `locomo --granularity dialog --rerank cross-encoder --chunk prod
--rerank-threads 2 --ingest-concurrency 2`; agent = OpenAI-compatible, `qwen3` @
`http://localhost:8080/v1` (API key passed at runtime, **never committed**).

1. `--agent off` → CE-alone baseline (fast; no LLM ingest). Fresh same-harness baseline rather
   than reusing the pre-`IndexTokensForKeyword` prior number.
2. `--agent anchors` → CE + anchors
3. `--agent typed` → CE + typed keywords
4. `--agent anchors,typed` → CE + both

The agent cache (`agent-{provider}-{model}.ndjson`) persists across cells, so anchors are
generated once and typed keywords once for the whole sweep. To quantify the generation-cost
difference, we measure the **size of the stored (parsed) outputs** — total characters / approx
tokens of the anchor text vs the typed-keyword text per doc. This is a proxy for output length
(it counts what was kept, not raw stripped generation), but it is sufficient to show the
order-of-magnitude token-economy difference the comparison turns on.

**Decision criterion:** typed ≥ anchors across R@5 / R@10 / R@50 / NDCG@10 → switch the prod
write slot to typed keywords (parity is a win once the token/latency savings are counted). The
`both` cell reveals whether the signals are complementary or redundant.

### 5. Testing

- Unit: `ParseTypedKeywords` (valid `entity:`/`topic:` lines; malformed dropped; dedup; cap;
  prefix validation). `AgentModes` parse + label for `typed` and combos.
- Bench integration: ingest a doc carrying typed keywords → assert they land on `entry.Keywords`
  and their value tokens appear in `TermFrequencies` (bench analog of `Store_TypedKeyword_ValueIsBm25Matchable`).
- Full `Scrinia.Retrieval.Benchmarks` test suite stays green.

## Non-goals (YAGNI)

- No `related:` / cross-links / graph (gated separately on the residual).
- No `date:` / temporal handling.
- No Scrinia.Core / prod changes (the `IndexTokensForKeyword` fix already shipped).
- No query-side prefix parsing (`search("entity:mary")`) — separate, smaller piece.

## Risks

- **Surface choice:** if LoCoMo dialog's pool gaps are smaller than finding #4 suggested, the
  signals may look near-equivalent. Mitigation: the `--agent off` baseline bounds the headroom;
  `both` and per-category numbers expose where any difference lives.
- **Agent ingest latency dominates wall-clock** (4–6 req/s). Mitigated by the shared cache —
  each signal generated once across all four cells.
- **Typed-keyword generation quality** depends on the model canonicalizing entities/topics well.
  Anti-leakage discipline (content-only) is mandatory; verify the prompt never receives gold/questions.
