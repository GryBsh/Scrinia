## Overall Assessment

**REQUEST_CHANGES**

The fix delta correctly removes the public `ArtifactUri` extension and the obsolete
`ResolveArtifactAsync` compatibility extension. The Task 3 contract is not yet closed,
however: raw string compatibility seams remain executable, and the new typed store members
have silent default implementations that can discard or misroute operations.

## Major Issues

### M1 — Raw-address compatibility bridges still bypass the typed contract

**Confidence:** 95%

`IPluginStore` retains `LegacyPluginStoreBridge` reflection over the old
`ReadArtifactAsync(string, string, CancellationToken)` shape (`src/Scrinia.Core/IPluginStore.cs:44-57`),
and `IMemoryEventSink` retains both reflection-based string callback invocation and string-address
extension overloads (`src/Scrinia.Core/IMemoryEventSink.cs:21-47`). These are executable aliases,
not merely migration comments: a pre-typed implementation can still receive a string generated by
`address.ToString()`. This conflicts with Task 3's required compile-time typed callback surface and
the plan's global constraint that `MemoryAddress` is the only supported address-construction path.

**Required fix:** remove the reflection/string callback bridges and update all in-repository
implementations and doubles to the typed methods. If compatibility is intentionally retained,
the plan/spec must explicitly authorize it and the conformance test must distinguish private
legacy storage migration from an executable public-contract fallback.

### M2 — Typed CRUD defaults silently do the wrong operation

**Confidence:** 90%

`IMemoryStore.ReadAsync` returns `null` unconditionally, `WriteAsync` ignores its address and
delegates only to `StoreAsync`, and `DeleteAsync` converts the address back to a string and always
targets the `local` scope (`src/Scrinia.Core/IMemoryStore.cs:66-77`). A store that compiles by
inheriting these defaults can report a missing read, write a payload at a different address, or
fail to delete a namespaced/ephemeral address without an error. That makes the typed contract
represent an operation while permitting a silent no-op or misroute.

**Required fix:** either make the typed members abstract and implement them at every store, or make
the defaults fail fast with a descriptive `NotSupportedException`; do not provide successful-looking
defaults that discard the typed address.

## Minor Issues

### m1 — Contract test does not enumerate all raw address-bearing store members

**Confidence:** 90%

`ContractTypingTests` checks only the three typed CRUD methods and selected plugin members. The
`IMemoryStore` still exposes raw address-bearing members such as `LoadIndex(string scope)`,
`Remove(string name, string scope)`, `ArchiveVersion(string subject, string scope)`, and
`WriteArtifactAsync(string subject, string scope, ...)` (`src/Scrinia.Core/IMemoryStore.cs:95-97,352-360`).
Some may be deliberately physical-boundary APIs, but the test does not classify or assert that
distinction, despite Task 3 requiring every address-bearing search/list/request property and typed
contract coverage.

**Required fix:** enumerate the full public surface, explicitly classify physical-boundary methods,
and assert that logical-address parameters are typed while only documented physical-boundary
parameters remain string-based.
