# Agent memory in 2026: a deep technical map

**The field has converged on a recognizable stack, but its hardest problems — temporal reasoning, conflict resolution, and adversarial robustness — remain unsolved.** Agent memory has matured from MemGPT's 2023 OS metaphor into a layered architecture combining typed long-term stores (episodic/semantic/procedural), hybrid retrieval (BM25 + dense + graph traversal), LLM-driven extraction with explicit update policies, and asynchronous "sleep-time" consolidation. The dominant production systems (Mem0, Zep/Graphiti, Letta, LangMem, Cognee, Honcho) disagree sharply on three axes: **vector vs. graph vs. file**, **append-vs-update**, and **agent-edits-memory vs. extractor-writes-memory**. Major model vendors have begun shipping memory as a first-class primitive (Claude's `memory_20250818` tool, ChatGPT's `bio` tool + chat history reference, Gemini's Personal Context). Benchmarks (LoCoMo, LongMemEval, MemoryAgentBench) show even the best systems lose 30%+ accuracy as histories grow, and recent attack research (MINJA, MemoryGraft, HackedGPT) demonstrates these systems are not yet defensible against motivated adversaries.

One important caveat up front: **the "Scrinia" project could not be located.** A comprehensive search across GitHub, PyPI, npm, Google, and the Polish AI engineering community (where the Latin etymology — *scrinium* = chest/repository; the Roman *scrinium memoriae* was literally the imperial office of memory — would resonate) returned no agent-memory project of that name. All hits are unrelated: 17th-century document collections (*Scrinia Sacra*, *Scrinia Reclusa*), a Croatian historical journal, ecclesiastical archives, and confusable names (Scrini AI hiring SaaS, Scry AI, Supermemory's "Scira"). The closest plausible Polish-authored agent-memory work is Adam Gospodarczyk's `Alice AGI` (github.com/iceener), but it is not Scrinia. If the project is private, pre-release, or known by another name, that context would unblock analysis; this report instead grounds the comparison in the published frameworks Scrinia would have to compete with.

## The cognitive scaffolding everyone now cites

The 2024 paper **CoALA — Cognitive Architectures for Language Agents** (Sumers, Yao, Narasimhan, Griffiths; arXiv 2309.02427) became the field's lingua franca. It maps Atkinson–Shiffrin's multi-store model (1968), Baddeley–Hitch's working memory (1974), and Tulving's declarative split onto an agent `A = (M_w, M_lt, A_i, A_e, D)` with **working memory** (the context window), **episodic** (past experiences), **semantic** (facts), and **procedural** (code/weights/prompts) long-term stores; **internal actions** (reasoning, retrieval, learning) write/read across them. Every memory framework now uses this vocabulary — Letta has `core` + `recall` + `archival`, LangMem ships explicit semantic/episodic/procedural primitives, MIRIX adds Core/Episodic/Semantic/Procedural/Resource/Knowledge Vault.

The cognitive grounding is not just nomenclature. **Ebbinghaus's forgetting curve `R = e^(-t/S)`** is implemented directly in MemoryBank (arXiv 2305.10250), where recall resets `t` and increases stability `S` — the same exponential decay (factor 0.995/hr) drives the recency term in Generative Agents. **Complementary Learning Systems theory** (McClelland, McNaughton, O'Reilly 1995) motivates the dominant background-consolidation pattern — fast hippocampal write → slow neocortical replay maps cleanly onto "sleep-time" agents (Letta), Honcho's Dream worker (runs every ~8h), and any system that summarizes/extracts asynchronously. **Hippocampal indexing theory** (Teyler & DiScenna) is the explicit motivation for HippoRAG's Personalized PageRank retrieval. And **Tulving's episodic/semantic distinction** — autobiographical events tagged with spatiotemporal context vs. context-free world facts — is what Mem0g, Graphiti, and A-MEM operationalize as distinct subgraphs or note types.

The single most influential operational pattern came from Stanford's **Generative Agents** ("Smallville," Park et al., arXiv 2304.03442). Its three-component memory stream — append-only log + reflection trees + weighted retrieval — is the canonical episodic→semantic consolidation mechanism. Its retrieval scoring function is now ubiquitous: `score = α_recency · exp(-decay·Δt) + α_importance · LLM_score(1–10) + α_relevance · cos(q, m)`, with all α=1 and importance ("poignancy") scored once at write time. **Reflection** fires when cumulative recent importance crosses a threshold (~150 in the paper): the agent self-prompts for the three most salient questions, retrieves evidence, synthesizes 5 high-level insights, and writes them back to the memory stream — recursively producing a multi-level abstraction tree. Ablations show all three retrieval signals are necessary; removing reflection alone degrades believability significantly.

## The system lineage from MemGPT to Letta, Mem0, A-MEM, Zep

**MemGPT** (Packer et al., arXiv 2310.08560) introduced the OS metaphor that the field has not displaced. The context window is "main context" (RAM) divided into system instructions, working context, and FIFO history; external context is split into "recall storage" (full event log) and "archival storage" (open vector DB). The LLM pages data via function calls (`archival_memory_insert/search`, `core_memory_append/replace`), with a "Memory Pressure" system warning at ~70% of max tokens and `request_heartbeat=true` enabling multi-step chains without yielding to the user. MemGPT achieved **93.4% on the Deep Memory Retrieval (DMR) benchmark** it introduced.

**Letta** (the team's 2024 rebrand) productionizes MemGPT into stateful agents with three innovations. First, **memory blocks** — labeled, character-bounded in-context regions (`persona`, `human`, custom) shareable across agents. Second, **sleep-time compute** (Lin et al., arXiv 2504.13171): an async background agent shares memory blocks with the primary agent but exclusively owns memory-edit tools, processing context during idle time via `rethink_memory()` → `finished_thinking()` loops. The paper reports a **~5× reduction in test-time compute** at equal accuracy on Stateful GSM-Symbolic/AIME, and **+13–18% accuracy** at scaled sleep-time compute; Multi-Query GSM-Symbolic amortizes ~2.5× cost/query when memory is reused. Third, **Agent File (.af)** serialization for portable stateful agents persisted in Postgres or SQLite. Letta is the cleanest production realization of CoALA's typed memory.

**Mem0** (Chhikara et al., arXiv 2504.19413, ECAI 2025) is the most production-deployed memory layer (AWS made it the exclusive provider for the Strands Agent SDK in May 2025). Its original architecture was a two-phase pipeline: (1) LLM extracts atomic facts from message pairs given a rolling summary; (2) for each fact, an LLM compares against top-k semantically similar existing memories and emits **ADD / UPDATE / DELETE / NOOP**. The graph variant **Mem0g** stores entities + relations as Neo4j triplets and traverses for multi-hop queries. Reported LoCoMo numbers: **66.9% LLM-judge vs. OpenAI Memory's 52.9% (+26% relative)**, with **91% lower p95 latency (1.44s vs 17.12s)** and **~7K tokens vs ~26K** for full-context. **Mem0's April 2026 algorithm reversal is the most interesting recent shift in the field**: they abandoned UPDATE/DELETE for a **single-pass ADD-only extraction with hybrid retrieval (semantic + BM25 + entity boost)**, pushing conflict resolution from write-time to retrieval-time, and reporting 91.6 LoCoMo / 93.4 LongMemEval / 64.1 BEAM-1M / 48.6 BEAM-10M. The flip reflects a genuine tradeoff: write-time consolidation reduces store size but locks in extraction errors and complicates audit; append-only preserves provenance but pushes complexity to ranking.

**Zep / Graphiti** (Rasmussen et al., arXiv 2501.13956) made the strongest case for graphs. Graphiti stores facts in a **bi-temporal knowledge graph** in Neo4j (or FalkorDB/Kuzu/Neptune), with four timestamps per edge: `t_valid` and `t_invalid` (when the fact was true in the world, timeline T) plus `t'_created` and `t'_expired` (when the system learned/invalidated it, timeline T'). The graph is hierarchical: an **episode subgraph** holds raw messages losslessly; a **semantic entity subgraph** holds extracted entities/facts; a **community subgraph** holds Leiden-style clusters. Crucially, **episodic edges link episodes to derived entities bidirectionally** — enabling auditable citations from any fact back to the source event. Edge invalidation handles supersession (e.g., "Alice was lead Jan 2025; Bob is lead since March 2025" sets Alice's `t_invalid = March 2025` without deleting the edge). Reported: **94.8% DMR vs MemGPT 93.4%; +18.5% LongMemEval accuracy with 90% latency reduction**. Mem0 and Zep have published cross-rebuttals on each other's benchmark configurations — the absence of a neutral harness is a real field-level problem that **MemoryAgentBench** (Hu et al., arXiv 2507.05257) is trying to fix.

**A-MEM** (Xu et al., arXiv 2502.12110) is the most architecturally distinctive recent system, applying the **Zettelkasten method** to agent memory. Each memory is an atomic note `{content, timestamp, keywords (LLM), tags (LLM), context_description (LLM), embedding, links}`. On insert, an LLM proposes explicit links to similar existing notes; in a step no other system does, **memory evolution lets earlier notes' context descriptions and tags get rewritten in light of new memories**. The network organically restructures. Retrieval is hybrid (embedding similarity + explicit-link traversal). A-MEM hits SOTA on LoCoMo across 6 foundation models, particularly on multi-hop and temporal categories.

The neurobiologically-motivated branch is dominated by **HippoRAG** (Gutiérrez et al., arXiv 2405.14831; NeurIPS 2024) and **HippoRAG 2** (arXiv 2502.14802; ICML 2025). HippoRAG performs offline OpenIE entity extraction into a KG ("artificial hippocampal index"), then at query time encodes the query entities, seeds them into the KG, and runs **Personalized PageRank** to diffuse relevance across nodes — passages are ranked by PPR-weighted node mass. Reported: matches iterative RAG (IRCoT) at **10–30× lower cost and 6–13× faster**, with up to **+20%** on multi-hop QA. HippoRAG 2 adds passage nodes as first-class graph members and online LLM filtering, beating standard RAG across factual (NaturalQuestions), sense-making (NarrativeQA), and associative (MuSiQue, 2Wiki, HotpotQA) tasks. **RAPTOR** (Sarthi et al., arXiv 2401.18059; ICLR 2024) is the complementary hierarchical-summary approach: chunk → GMM-cluster (soft assignment via UMAP) → LLM-summarize → recurse, with retrieval over the "collapsed tree" empirically beating tree traversal.

## What each major framework actually does

The production landscape has split into roughly seven architectural archetypes. The table below collapses the most important distinctions.

| **Zep/Graphiti** | Temporal knowledge graph (Neo4j/FalkorDB/Kuzu) | Cypher + cosine + BM25 + BFS, RRF fusion | Episode → entity extraction → edge invalidation | **Bi-temporal model (T, T'); 4 timestamps per fact** | Graphiti Apache-2.0; Zep cloud |

Three patterns crystallize. **First, hybrid retrieval is now table stakes** — every serious system combines dense embeddings, BM25 sparse signals, and either graph traversal or cross-encoder reranking, typically fused via Reciprocal Rank Fusion (`score(d) = Σ_r 1/(60 + rank_r(d))`) to avoid the BM25-vs-cosine scale mismatch. **Second, sleep-time / background consolidation is the next frontier** — Letta sleep-time agents, Honcho Dream/Deriver workers, MemoryScope frontend/backend separation, Cloudflare Agent Memory's async pipeline (Llama 4 Scout for extraction, Nemotron 3 120B for synthesis), and Mem0's async post-response extraction all move heavy memory work off the inference hot path. **Third, only LangMem currently supports true procedural memory** — letting the agent rewrite its own system prompt from feedback. Letta supports core-block edits but persona/instructions remain user-defined; Voyager-style skill libraries are procedural memory but require code-execution environments.

## Major products converged on a dual-layer pattern

The consumer assistants — **ChatGPT, Claude, Gemini, Copilot, Perplexity** — have independently converged on the same two-layer memory architecture: **explicit "saved memories"** (user-controllable, often viewable) plus **implicit "chat history reference"** (auto-inferred profile/preferences, less transparent). All offer per-project/workspace isolation, Temporary/Incognito modes, and tenant-region data residency for enterprise.

The architectural outlier is **Anthropic**. Claude's memory deliberately eschews vector retrieval in favor of transparent, editable **CLAUDE.md Markdown files** with hierarchical precedence (enterprise → user → project → local). The September 2025 **Memory Tool API** (header `context-management-2025-06-27`) exposes a client-side `/memories` directory with `view/create/str_replace/insert/delete/rename` commands — Anthropic provides only the tool spec; the developer implements storage. Anthropic's published numbers: **84% token reduction** in a 100-turn web search evaluation and **39% improvement** on agentic search when memory + context editing are combined (internal benchmarks). The philosophical bet — auditable files over opaque vector DBs — trades scalability for user control and is increasingly cited in coding-agent design (Cline's Memory Bank, Cursor Rules, AGENTS.md all follow the same pattern).

**ChatGPT's mechanics** are well-reverse-engineered (embracethered.com). The system prompt contains a "Model Set Context" section with timestamped saved memories (e.g., `[2025-05-02]. The user likes ice cream.`) populated via a `bio` tool, plus an "Assistant Response Preferences" section with auto-inferred preferences and confidence levels (high/med/low). The April 2025 "Reference chat history" feature appears not to do semantic search across all past chats but maintains a separate evolving profile from recent history; Plus/Pro/Team/Enterprise/Edu only (June 2025 brought a "lightweight" version to free users). Per-Project memory is isolated; Temporary Chat bypasses both layers; deletions soft-delete with 30-day retention.

**Gemini** auto-extracts preferences (Personal Context, August 2025), enabled by default except under-18s/EEA/CH/UK; "Gemini Apps Activity" was renamed "Keep Activity" (off by default for prior opt-outs). **Microsoft 365 Copilot Memory** (GA July 2025) stores per-tenant, region-localized memory subject to DLP/sensitivity labels — invisible even to admins per user. **Windows Recall** is a distinct system-level feature (NPU-based on-device screenshot OCR + embedding) that shipped vulnerable, was relaunched April 2025 as opt-in with BitLocker + Windows Hello + hardware encryption. **Perplexity's** notable design decision is decoupling memory from the model — switching between GPT-4o/Claude/Gemini mid-session preserves context, and memories that influence a response are surfaced as citations alongside web sources.

## Use case divergence: memory needs are not universal

What memory needs are universal versus domain-specific is the most under-appreciated question in this space. **Coding agents** need code-aware structural indexing (not just text similarity), repo conventions, and a queryable codebase representation. Aider's **repo map** is the most refined example: tree-sitter extracts `name.definition.*` and `name.reference.*` tags across 130+ languages into a `MultiDiGraph`, then **Personalized PageRank** ranks files for the current context — chat files weighted 50×, mentioned identifiers 10×, well-named symbols (≥8 chars) 10×, reference counts square-rooted to avoid dominance. Token budget controlled by `--map-tokens` (default 1k). Cline's **Memory Bank** mandates reading six hierarchical Markdown files (`projectbrief.md`, `productContext.md`, `activeContext.md`, `systemPatterns.md`, `techContext.md`, `progress.md`) at the start of every task, plus `.clinerules` as a "learning journal." Cursor's `.cursor/rules/*.mdc` files have four activation modes (Always, Auto Attached by glob, Agent Requested, Manual). Cognition Devin's distinctive primitives are **Knowledge** (key/value blobs with auto-generated "DevinAI uses this when..." retrieval descriptions), **Playbooks** (reusable specs), **Machine Snapshots** (resumable state with repos cloned and env set up), and **DeepWiki** (auto-generated architectural wiki). Notably, Sourcegraph Cody **abandoned embeddings** for codebase context in favor of native search + SCIP code-graph + reranking, because embeddings missed cross-file callers and required shipping source code to third-party APIs.

**Customer support agents** (Sierra, Decagon, Intercom Fin) need CRM-joined customer records, cross-channel continuity, and auditable action logs. Sierra's "Agent Data Platform" (Nov 2025) unifies unstructured chats/emails/calls with structured CRM/billing data into a single memory layer behind one persona, routing across a "constellation" of 15+ models. Decagon centers on Agent Operating Procedures — natural-language playbooks for compliance. **Companion agents** (Replika, Character.AI, Pi) need months-long emotional continuity; Convai's open architecture uses a memory tree keyed by `speaker_id` with three retrieval dimensions (recent, long-term, latent) and explicit emotional-significance ranking. Failure mode: Replika 2.0's April 2026 memory-architecture rebuild caused widespread memory loss and personality drift. **Research agents** need per-claim provenance: Anthropic's research system uses an orchestrator + worker pattern with a Citation Agent and **artifact pattern** (subagents write artifacts to shared file storage and return references, avoiding the "telephone game" of long chat returns), reportedly outperforming single-agent Claude Opus 4 by 90.2% on internal research evals at ~15× the tokens. **Autonomous agents** need procedural skill libraries: Voyager (arXiv 2305.16291) stores successful behaviors as **executable JavaScript functions indexed by docstring embeddings**, achieving 3.3× more unique items and 15.3× faster tech-tree progress than baselines; ablations show removing the skill library drops discovered items ~93%. Manus's file-system memory uses `todo.md` as a live checklist explicitly "to manipulate attention" so the model keeps re-reading the goal across typical 50-tool-call tasks, with the design principle that compression must be **restorable** (file paths remain in context even when content is dropped).

## The patterns that determine production success

The patterns most worth understanding deeply are the ones that determine whether a memory system actually works in production. Five matter most.

**Writing policy is the highest-leverage decision.** Mem0's evolution from ADD/UPDATE/DELETE/NOOP (2024) to single-pass ADD-only (2026) is the field's clearest example of an experienced team flipping its position. Update-heavy systems lock in extraction errors, complicate audit, and force the field's hardest call — when does a new fact supersede an old one? — into write-time when the agent has the least information. Append-only systems push that decision to retrieval, where it can be informed by the actual query, but they grow unboundedly and need stronger ranking. **Graphiti's bi-temporal model is the only widely-cited production answer that does neither**: facts are never deleted, but `t_invalid` and `t'_expired` mark supersession explicitly, allowing both audit ("what did we believe last Tuesday?") and current-truth queries ("what's true now?") via simple filters. A-MEM's memory evolution — letting earlier notes be rewritten when new ones arrive — is a third path, but no production system has adopted it.

**Retrieval is now multi-signal.** The Generative Agents scoring function `α_recency · exp(-decay·Δt) + α_importance · LLM_score + α_relevance · cos(q,m)` remains the foundation, but production systems extend it with BM25 (catching exact-match items dense search misses), graph traversal (multi-hop reasoning), and reranking. **Reciprocal Rank Fusion (k=60)** dominates because it sidesteps the BM25-vs-cosine scale mismatch. **Maximal Marginal Relevance** with λ ≈ 0.5–0.7 handles a real production failure: one long session's chunks flooding top-k results (a documented case showed 66% of retrieved chunks from a single transcript in 41% of test queries). AWS Bedrock AgentCore tunes recency decay half-life by domain — minutes for monitoring agents, hours for support, weeks for account management. The cross-encoder rerank stage adds 50–200ms but is largely cacheable; one practitioner reports 80% query repeats yielding 75% GPU savings.

**Long context does not obviate memory**, despite Gemini 2.5's 1M+ token windows. **Lost-in-the-middle** (Liu et al., arXiv 2307.03172) still degrades multi-hop tasks meaningfully even on modern models, driven by RoPE long-term decay and attention biases. **Context rot** (Chroma's research across 18 frontier models) shows accuracy drops well before nominal limits — at 10K tokens there are 10⁸ pairwise attention relations to maintain; at 100K, 10¹⁰. Mem0's reported numbers make the cost case directly: 91% lower p95 latency (1.44s vs 17.12s) and 70–85% token reduction at equal or better accuracy. Anthropic's "context engineering" framing — find the smallest set of high-signal tokens that maximize outcome likelihood — is now the dominant mental model, with memory positioned as one primitive alongside compaction, tool-result clearing, and sub-agents.

**Sleep-time / background consolidation has emerged as the most important architectural pattern of 2025.** Letta's sleep-time compute paper (arXiv 2504.13171) is the clearest formalization: an async agent shares memory blocks with a primary agent but exclusively owns memory-edit tools, processing context during idle. Reported gains — 5× test-time compute reduction, +13–18% accuracy when sleep-time compute is scaled, 2.5× cost/query reduction when memory is amortized across related queries — only apply when context is reused across queries (a strong production assumption). The same architectural move appears in Honcho (Dream worker every ~8h merges redundant observations and infers higher-level patterns; Deriver worker extracts conclusions per message batch), MemoryScope (frontend retrieval / backend consolidation workers), Cloudflare Agent Memory (Llama 4 Scout for extraction, Nemotron 3 120B for synthesis), and Mem0's async post-response extraction. The pattern decouples memory maintenance latency from user-facing response latency — a real win.

**Security is dangerously underdeveloped.** This is the section practitioners most consistently underweight. The attack surface has three layers. **Memory poisoning**: AgentPoison (arXiv 2407.12784) is the canonical backdoor attack on RAG-based agents; MINJA (2025) achieves **>95% injection success and ~70% attack success** via query-only memory injection; MemoryGraft (arXiv 2512.16962, Dec 2025) plants malicious "successful experiences" that execute weeks later when semantically triggered — defenses targeting prompt-level attacks fail because the malicious belief is now legitimate stored memory. **Prompt injection via stored memories**: the Schwartzman ChatGPT exfiltration paper (June 2024) demonstrated persistent cross-session data theft; ZombAI / ZombieAgent (Radware, Oct 2024) plants memory via attached files for dynamic remote control; HackedGPT (Tenable, Nov 2025) documents seven vulnerabilities including 0-click via SearchGPT browsing context and markdown rendering bugs to hide malicious content. The Promptware Kill Chain analysis (arXiv 2601.09625, 2026) shows lateral movement growing across cohorts: 0/3 → 3/12 → 8/21 from 2024 to 2025–2026. **Privacy**: GDPR right-to-be-forgotten is structurally hard on append-only graph stores; Graphiti's bi-temporal can invalidate but not remove without breaking audit chains. Memory namespacing (every memory tagged with `user_id`) solves cross-user leakage but not in-namespace poisoning. No production system has a robust defense; research-stage proposals (RevPRAG activation analysis, "memory contracts," belief-drift detection) are not yet usable.

## Benchmarks, and why the benchmark wars matter

Evaluation has converged on a small set of benchmarks with known limitations. **LoCoMo** (Maharana et al., arXiv 2402.17753; ACL 2024) constructed 10 conversations of up to 32 sessions / 600 turns / 16K tokens / 6–12 simulated months with 200–300 probe questions per conversation; human F1 is 87.9 while GPT-3.5-16K hits 37.8 and the best original RAG ~41.4. Mem0, A-MEM, Zep, MIRIX, and most newer systems benchmark here. **LongMemEval** (Wu et al., arXiv 2410.10813; ICLR 2025) defines the now-canonical taxonomy of five memory abilities: Information Extraction, Multi-Session Reasoning, Temporal Reasoning, Knowledge Updates, and Abstention. It tests at two scales (LongMemEval_S ~115K tokens / ~50 sessions; LongMemEval_M ~1.5M tokens / ~500 sessions) and produces the field's most important headline result: **commercial systems drop ~30% when going from short to long histories**; ChatGPT (GPT-4o) goes from 91.8% (full offline reading) to 57.7% (online memory). Knowledge Updates is the hardest competency — common failure: knowledge overwrite or compression of older facts. **MemoryAgentBench** (Hu et al., arXiv 2507.05257) restructures long-context datasets into incremental multi-turn streams plus new datasets (EventQA, FactConsolidation) to probe four competencies including conflict resolution — current memory agents are *especially weak* here. **MemBench** (arXiv 2506.21605, ACL 2025) stresses capacity scaling with metrics including temporal efficiency.

The benchmark wars matter because Mem0 and Zep have published cross-rebuttals on each other's configurations: Mem0's paper reports beating Zep on LoCoMo; Zep counters that Mem0 misconfigured them (corrected ~75.14%) while Zep's own footprint is >600K tokens/conv with hours of background processing. The field lacks a common evaluation harness — MemoryAgentBench and the Letta Leaderboard are attempts to fix this. **Vendor benchmarks should be read with this in mind**: Anthropic's 84% token reduction / 39% agentic improvement numbers, Supermemory's 85.4% LongMemEval-S, Honcho's published gains, and Mem0's April 2026 algorithm numbers are all self-reported.

## Where Scrinia would have to compete

Since Scrinia could not be located, the productive question is what design space remains genuinely contested — i.e., where a new system could differentiate. Three open problems stand out.

First, **temporal reasoning at scale**: Graphiti's bi-temporal model is the strongest production answer, but it's tied to Neo4j-class graph stores with operational cost most teams don't want. Memobase's event timeline is simpler but coarser. The space for a temporally-rigorous memory system on simpler infrastructure (Postgres + pgvector with explicit valid-time/transaction-time columns) is empty. Second, **conflict resolution as a first-class competency**: MemoryAgentBench shows every current system is weak here, Mem0's algorithm reversal demonstrates the field doesn't have consensus, and the underlying question — how to detect that "user moved to Bangalore" supersedes "user lives in Mumbai" without LLM-extracting from every new memory — has no clean answer. Third, **adversarial robustness**: MINJA's 95% injection rate against current systems means anyone shipping memory to enterprise customers is shipping a vulnerability; "memory contracts," provenance tracking, and write-time validation against stable user-asserted facts are research-stage primitives waiting for productization. **Procedural memory beyond LangMem's "agent edits own prompt"** is also open — Voyager-style skill libraries are domain-specific (Minecraft), and no general framework lets agents accumulate reusable procedures across tasks.

Any system named Scrinia — invoking the Roman *scrinium memoriae* etymologically — would be evaluated against this landscape: does it solve temporal reasoning more cheaply than Graphiti, conflict resolution more reliably than Mem0, security more rigorously than current frameworks, or procedural memory more generally than LangMem? Without code to examine, that assessment cannot be made; but the design slots where a defensible new system could differentiate are now well-defined.

## What's actually known, and what isn't

The field has consolidated remarkably fast — three years from MemGPT's OS metaphor to a shared vocabulary (CoALA's typology), a shared scoring function (Generative Agents' recency·importance·relevance), a shared write-policy debate (append vs. update), and a shared async-consolidation pattern (sleep-time agents). The remaining disagreements are productive: **vector vs. graph vs. file** (Anthropic's file-based bet vs. Zep's graph bet vs. Mem0's vector bet), **agent-controlled vs. extractor-controlled writes** (Letta vs. Mem0/Zep), and **write-time vs. retrieval-time conflict resolution** (Mem0 2024 vs. Mem0 2026).

What's not yet known and matters most: whether **bi-temporal modeling generalizes** beyond Graphiti's Neo4j footprint; whether **procedural memory** can be made first-class outside narrow domains; whether **adversarial robustness** can be achieved without sacrificing the open-ended writes that make memory useful; and whether **long-context models** will eventually compress the memory problem into a context-engineering problem (the evidence so far — cost, latency, lost-in-the-middle, context rot — says no, but the slope of improvement matters). The honest answer is that production agent memory in 2026 is closer to a stack of well-understood techniques than to a solved engineering problem, and the gap between "publishable benchmark wins" and "memory that adversaries can't trivially poison" remains the field's most important open frontier.
