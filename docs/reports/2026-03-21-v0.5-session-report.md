## 5. Security Posture

### Hardened
- CORS restrictive by default (empty = deny all)
- Health details require `health` permission
- Chat requires `chat` permission
- API keys salted with per-key 16-byte random salt
- SQLite access serialized via ReaderWriterLockSlim
- Per-user rate limiting (userId for auth, IP for unauth)
- LLM provider keys server-side only (never sent by clients)
- Agent has read-only store access (search + recall only)
- Gemini API key in header (not URL)
- Tool errors sanitized before reaching LLM
- Config validated at startup (RateLimit, Temperature, MaxTokens) — silent DoS prevention
- Chat provider errors include HTTP status codes for operator visibility
- JSON parse catches narrowed to JsonException (no bare catches in SSE parsing)
- Corrupt zip imports caught with correct exception type
- Orphaned temp files ignored by git

### Chaos Engineering (G-17)
Probed 6 failure domains across 3 parallel agents. Key findings:
- **Config domain**: RateLimit=0 was a silent DoS (fixed), chat options validated at startup
- **Network domain**: Provider errors lacked status codes (fixed), JSON parse was too broad (fixed)
- **Storage domain**: Corrupt zip wrong exception type (fixed), temp file accumulation (fixed)
- **Concurrency domain**: Clean — FileLock + ReaderWriterLockSlim handle all probed scenarios
- **Resource domain**: LRU cache bounded correctly, search results capped, no unbounded allocations
- Debugger agent validated all dismissals: 6 correct, 1 wrong (promoted and fixed)

### Accepted Risks (all debugger-verified)
- CORS AllowAnyHeader/AllowAnyMethod (needed for MCP)
- ApiKeyStore/EmbeddingsTools without TypeInfo (not trimmed)
- ValidateKey TOCTOU on last_used_at (harmless)
- IPv4/IPv6 partition key inconsistency (edge case)
- X-Forwarded-For not handled (deployment config)

### Breaking Changes
- CORS: empty `CorsOrigins` now denies all (was allow-all). Use `["*"]` to restore old behavior. `appsettings.Development.json` provides this for dev.
- Health: `/health/ready` and `/health` no longer return checks array. Use `/health/details` (requires `health` permission) for full diagnostics.
- Web admin `getHealth()` now calls authenticated `/health/details`. API keys need `health` permission for dashboard store list.
- Config validation: RateLimit PermitLimit/WindowSeconds ≤ 0 now logs warning and resets to default (was silent DoS).
- Chat Temperature clamped to [0.0, 2.0], MaxTokens reset to 4096 if ≤ 0.
- Bundle types (BundleIndex, BundleManifest, BundleJsonContext) moved from Scrinia.Mcp to Scrinia.Core.Bundles. Code referencing `Scrinia.Mcp.BundleIndex` must update to `Scrinia.Core.Bundles.BundleIndex`.
